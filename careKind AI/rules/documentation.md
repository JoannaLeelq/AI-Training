# 分层目录与 AI 文档规范

## 三类文档各自的职责

- `AGENTS.md`：给 Codex 和其他 agent 的执行说明，记录当前目录的职责、边界、必须查阅的来源、关键不变量和验证方式。文件名固定为复数大写 `AGENTS.md`。
- `CLAUDE.md`：Claude Code 入口，使用单独一行 `@AGENTS.md` 导入同目录规范；确有工具专属事项时再追加，避免复制出两份独立规则。
- `README.md`：给人和 AI 的目录说明，介绍用途、真实结构、主要入口、依赖和使用方法。不把尚未实现的内容写成已存在。

## 放置层级

| 位置 | 要求 |
|---|---|
| 工作区/仓库根目录 | 三个文件，说明仓库边界和项目入口 |
| 公司项目根目录 | 三个文件，指向 rules、skills、workflows、共用 PRD 与部门 |
| 部门目录 | 三个文件，记录部门职责、输出位置和特有约束 |
| 大型功能模块目录 | 创建模块或按 CR-16 拆分时建立三个文件，说明公开入口、输入/输出、依赖、失败行为及适用测试命令 |
| 单个复杂函数 | 在函数所在模块的 README/AGENTS 中说明相关契约，函数附近写“为什么”的注释和类型；函数本身不能承载目录说明文件 |
| 简单工具函数/小文件 | 沿用父目录说明，避免为每个小文件创建重复说明 |

大型功能模块按独立职责/边界识别，例如采集、转写、归属、审核或导出；只在实际创建对应代码目录时补文档，不预造未实现模块。

## 维护规则

- 根说明保持简短；子目录只补充该范围的信息，引用共同规范，不重复整份公司规则/PRD。
- 子目录描述可以细化职责，但不得静默放宽原始反馈、隐私、权限和签署等共同不变量。
- 修改文件前查阅所在路径上适用的 AGENTS.md；从仓库根启动时也要主动读取相关子目录规范，不假设工具已经加载所有后代目录。
- 结构、公共接口、配置或验证命令改变时同步相关 README/AGENTS；CLAUDE 保持导入有效。
- 只写真实可运行命令和已存在入口。尚无应用或测试工具时说明未配置，不填写猜测命令。

官方入口说明：[Codex AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md)、[Claude Code 共享说明导入](https://code.claude.com/docs/en/memory)。
