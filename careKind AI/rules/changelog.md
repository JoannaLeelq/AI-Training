# AI 修改记录规范

## 记录位置和触发条件

公司根目录 `CHANGELOG.md` 是 AI 修改的共用时间线。Codex、Claude 和其他协作 agent 每次实际新增、修改、移动或删除项目文件，都必须记录；包括代码、PRD、运营/HR 文档、rules、skills、workflows 和目录入口说明。只读查询且没有修改无需记录。

“每次”以一个有明确目的的修改批次为单位：一次相关修改可合并一条记录，但每个受影响文件和操作都要列出。连续任务涉及不同目的/独立批次时分开记录。任务中断或未完成但已保存修改，也要记录实际状态；不能因为未交付就漏记。

工作区/仓库入口文件为 careKind AI 进行的修改也记在此时间线。详细 workflow run 可作为证据链接，不能替代 changelog；小型修改可以没有 run record，但仍需 changelog。

## 每条记录的必填字段

- **ID：** 唯一标识，如 `CK-YYYYMMDD-NNN`；追加前查阅已有 ID，避免冲突。
- **日期/时间：** Australia/Sydney，包含实际时区偏移（有真实时间时）；不知道时分就注明未记录，不编造时间。
- **执行者：** Codex / Claude / agent 名称；模型名只有已知时填写。
- **类别与原因：** code / product / operations / people / rules / research / docs 等，以及对应请求/需求编号或修改目的。
- **状态：** complete / partial / blocked / reverted；记录实况，不把未通过检查写为完成。
- **文件与操作：** 项目相对路径、Add / Modify / Move / Delete、必要的旧/新路径。
- **变更说明：** 实际改变的行为、规则或资料，避免只写“优化”“更新”。
- **检查结果：** 实际执行的检查、结果；未执行或失败的部分说明原因。
- **影响/待办：** 相关限制、剩余事项或明确的“无”；需要时链接 workflow run、提交或其他证据。

## 保存与修改纪律

- 按发生顺序追加到文件末尾；不能用最新记录覆盖历史。完成后的错误记录用新的更正条目引用原 ID，不静默重写历史。
- 同一当前修改批次的未完成条目可补齐检查结果再完成；完成后任何新的文件修改进入新条目。
- 更新 changelog 本身归入该批次，不为“记录了记录”无限生成新条目。
- 多 agent 由协调者汇总或按顺序追加；写入前重新读取末尾和最新 ID，禁止覆盖其他 agent 的新增记录。
- 记录文件路径、类别和影响，不复制秘密、住户/员工敏感内容、原始反馈或完整录音/对话。存在敏感改动时只记非敏感摘要。
- 从规则启用时开始逐次记录。历史回填必须注明是回顾性整理，并给出依据；没有证据不得补造历史修改、作者、时间或验证结果。

这是团队和 AI 工作流的记录要求；目前不代表存在后台监听、Git 钩子或不可篡改审计服务。
