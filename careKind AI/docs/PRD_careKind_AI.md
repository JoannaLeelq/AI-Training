## 1. 产品概述

careKind AI 是帮助养老护理人员完成日常 paperwork 的 AI 文书助手。护士在一班次（例如 8 小时）内，通过获授权的录音采集护理对话和口述观察；系统持续转写、识别护理事件、按老人组织信息，并生成每位老人的护理记录草稿。护士可在班次中或班次结束时核对、修改和签署，将审核通过的内容导出或写入机构的正式记录系统。

产品还为每位老人维护可追溯的情况记录和时间线，展示已经确认的观察、护理行为、本人诉求、相关人员转述及后续跟进。它记录事实及来源，保留“不知道”和“未记录”的状态，帮助护士完成准确、及时的文书。

**一句话价值：** 将一个班次中分散的护理信息，整理成按老人归属、按时间排列、能够回查来源并由护士确认的记录。

**发展方向建议：** 围绕“多老人班次记录与证据链”建立产品，先用身份标记加自动整理证明价值，再逐步降低标记成本。首版以 progress notes 和交班摘要切入，以接入现有机构记录系统完成交付闭环。8 小时是班次处理能力与耐久指标；实际采集由合法授权和护理场景控制。详细市场依据、突破假设、实现逻辑与团队工作流见第 18–21 节。

### 已确认的产品方向

- AI 辅助完成 aged-care paperwork。
- 支持约 8 小时班次录音的处理。
- 自动分配各位老人的相关内容，生成个人数据和文档。
- 记录老人具体情况，便于连续照护和交班。

以上来自 Joanna 的产品描述。本文新增的默认流程、指标、技术容量和阶段安排均为设计提案；未宣称已完成开发、验证或获得监管批准。

## 2. 用户与使用场景

| 用户 | 主要需求 | 权限原则 |
|---|---|---|
| 护士 / 获授权的护理人员 | 班次录音、核对老人归属、补充事实、审核草稿、完成记录 | 仅访问授权机构/区域/老人；正式记录签署按机构岗位权限 |
| Nurse in Charge / 临床负责人 | 查看班次记录完成情况、处理归属或内容疑问、交班审核 | 按机构临床管理权限访问，保留访问审计 |
| 机构管理员 | 维护老人名册、用户权限、录音政策、模板、保留周期和集成 | 管理权限不自动赋予全部临床内容查看权限 |
| 老人及获授权代表 | 知道哪些信息被采集、选择替代记录方式、申请访问或更正 | 通过机构已有的权利与授权流程处理 |

首版面向单一试点机构内的指定区域和护士班次。Home care、多机构跨班次协作和家属门户留到后续阶段。

## 3. 问题与目标

### 当前问题假设（需要访谈验证）

- 护理信息散落在对话、临时笔记和班后回忆中，重复填写文书耗时。
- 一个班次涉及多位老人，事后容易混淆归属、事件发生时间和护理动作。
- 转述、计划与实际执行容易被混写；生成摘要后难以查证原始依据。
- 不同记录系统和机构模板导致重复录入。

### 产品目标

1. 减少整理和重复录入的时间，同时保留有意义的审核过程。
2. 每条候选记录都有明确老人归属或可见的“待确认”状态。
3. 护理记录中的关键事实、时间、作者和来源可查证。
4. 让护士快速查看每位老人本班次发生了什么、哪些事项仍需确认。
5. 支持机构既有临床、隐私、记录保存与审核流程。

首版不执行自主诊断、病情评分、分诊、给药或治疗建议；不根据背景声音判断老人发生了跌倒或病情恶化。紧急照护继续使用机构现有流程，不能等待 AI 转写或提示。

## 4. 产品范围与阶段

| 阶段 | 交付范围 | 进入条件 |
|---|---|---|
| 可行性原型 | 合成/模拟录音、分段转写、老人标记、自动组织、来源回查、审核体验 | 明确需求；不用真实住户数据 |
| MVP 受控试点 | 8 小时班次会话、授权录音窗口、身份绑定、待确认队列、老人时间线、护理记录草稿、人工审核、导出、审计 | 隐私/录音/临床安全评估及现有试点准入清单通过 |
| 下一版本 | 选定机构记录系统集成、多护士同一老人记录协调、更多文书模板和经评估的语言支持 | 试点证据支持；集成、权限与数据流评估完成 |
| 长期目标 | 更少手动标记、更稳健的整班次环境音理解和多场景扩展 | 身份归属及隐私控制有充分证据；重新评估用途与法规 |

**8 小时的含义：** 一个逻辑班次可覆盖 8 小时，也可处理获授权的累计/连续 8 小时音频。使用者始终能够暂停或停止采集。实际连续环境录音只在被批准的场景和时间窗口启用，不能用“8 小时班次”默认授权录下所有人、所有场所和所有对话。

## 5. 核心用户旅程

1. **班前准备：** 护士登录，选择机构/区域、班次和获授权老人名册；检查设备、录音授权状态和网络。
2. **开始录音：** 页面清楚显示录音状态；护士确认照护对象，建立一次 encounter（护理接触）标记，可选择老人或扫描机构身份标记并核对。
3. **持续处理：** 录音分块保存与上传；AI 转写、切分相关护理事件，保留时间和说话人线索，并按可信 encounter/身份信息生成归属候选。
4. **自动整理：** 确定性身份标记支持的内容进入相应老人草稿工作区；其他内容进入“待确认归属”。发生主题或对象切换时重新判定，不延续上一位老人直至班次结束。
5. **班中检查：** 护士可查看草稿、纠正归属、补充记录或排除非护理内容。任何人工补充均标记为人工输入，不伪装成录音原话。
6. **班后审核：** 按老人查看时间线和进度，检查重要数值、否定表达、护理动作、转述和事件时间；处理待确认项。
7. **签署与交班：** 获授权人员主动确认记录，导出或提交；草稿状态、签署人和版本可查，提交失败可安全重试。

```mermaid
  A[班次与录音授权] --> B[分段采集/上传]
  B --> C[转写与事件切分]
  C --> D{老人归属依据}
  D -->|可信身份标记| E[对应老人草稿]
  D -->|不足或冲突| F[待确认队列]
  F --> G[护士确认归属]
  G --> E
  E --> H[护士核对来源和事实]
  H --> I[主动签署]
  I --> J[导出/正式系统提交]
```

## 6. 老人归属规则——核心产品要求

### 6.1 三种身份必须区分

- **说话人：** 谁说了这句话。说话人分离输出可以只是 Speaker 1/2，并不等于某位老人。
- **被提到的人：** 对话提及哪位老人、家属或同事。
- **记录对象：** 此条护理事实应属于谁。

例如护士对 A 老人说“B 今天没有吃早餐”，不能因为 A 正在对话就把 B 的情况记入 A。多人共同活动的片段不能整体复制进所有老人的档案。

### 6.2 身份依据与处理

| 依据 | 首版处理 |
|---|---|
| 护士选定稳定 resident ID，并核对两个机构认可的身份要素 | 建立有时间边界的 encounter；支持自动组织到该老人草稿，护士仍需审核 |
| 机构 QR/条码等身份标记 | 扫描后展示身份供确认；它不是自动可信的临床签署 |
| 音频中清晰提及姓名或机构批准的身份口令 | 作为归属线索；同名、误读或冲突时要求确认 |
| 房间号、当前位置、排班列表 | 仅为辅助线索；单独不足以确认身份，房间可更换或多人同住 |
| 声音相似或说话人分离结果 | 不作为老人身份确认。首版不建立声纹身份库 |
| 无身份、多人讨论、切换不明或线索矛盾 | 进入待确认队列，禁止自动写入正式记录 |

### 6.3 必须具备的行为

- 身份归属和内容准确性分开校验；“转写清晰”不代表“老人归属正确”。
- 置信度只能辅助排序，不能单独授权提交。模型自报置信度未经校准，不可作为可靠概率展示。
- encounter 结束、对象切换、超时或录音恢复后重新确认上下文；超时值通过试点确定。
- 一个片段包含多位老人时拆出有证据的独立事实；无法拆分的部分保持未归属。
- 护士改错归属后，撤回旧老人草稿中的相关内容并保留审计；签署后的更正走机构正式修订流程。
- 未归属项不隐藏、不当作已完成。护士可以确认归属、标记非护理内容，或注明未解决并交接；系统不强迫猜测。

| FR-07 | P0 | 老人自动归属 | 实现第 6 节规则；可靠 encounter 内容按老人自动组织；同名、冲突、多人或无依据内容进入待确认；跨机构名册永不匹配 |

| FR-09 | P0 | 护理事实提取 | 区分本人诉求、护士观察、他人转述、计划/执行/拒绝/未知；保留单位、否定、时间与信息来源；无记录不等于正常 |
| FR-10 | P0 | 每位老人记录与时间线 | 按实际/描述的事件时间显示已签署记录；AI 草稿分区展示；录制时间与事件时间可不同；缺少信息标注未记录 |
| FR-11 | P0 | 文书生成 | 基于已归属事实生成机构批准的 progress note 草稿和班次交班摘要；每项关键事实链接来源；不新增诊断、护理动作或正常结论 |

| FR-13 | P0 | 导出、版本与审计 | 首版选定一种机构可接受的导出格式；导出保留 resident ID、作者、事件/签署时间及版本；未经签署的导出标注草稿 |
| FR-14 | P0 | 老人情况手动补充 | 可登记机构允许的基础资料和补充事实，注明作者、来源、时间及是否确认；区分现行资料与历史信息，不自动覆盖机构原档案 |
| FR-15 | P0 | 保留、删除和授权访问 | 音频/文本/草稿/正式记录按独立规则管理；删除包括供应商副本和本地缓存；法律保留与备份到期可追踪；访问/更正请求可处理 |
| FR-16 | P0 | 人工替代与故障处理 | 录音拒绝、设备故障、模型超时、余额不足或系统不可用时允许手动记录；显示具体处理状态，不阻碍机构照护/交班流程 |
| FR-17 | P1 | 机构记录系统集成 | 采用客户确认接口和字段映射；签署后提交，重试有幂等标识；确认目标老人和返回结果；更正/撤销与客户系统规则一致 |
| FR-18 | P1 | 多护士协作与重复处理 | 同一老人跨会话内容显示来源和作者；相似事件建议复核，不自动删掉不同时间的重复护理动作 |
| FR-19 | P1 | 更多模板及语言支持 | 扩展到事件记录草稿、机构表单及经验证的语言；翻译保留原文来源；未验证语言明确提示限制 |

## 8. 老人“具体情况”记录范围

| 维度 | 可记录内容 | 约束 |
|---|---|---|
| 身份与护理背景 | 稳定 ID、显示名、机构/区域、机构提供的护理背景 | 按必要性与权限访问；身份信息不靠音频猜测 |
| 老人表达 | 不适、疼痛描述、需求、偏好、拒绝 | 标明本人表达；没有疼痛评分就不生成评分 |
| 日常活动 | 饮食饮水、活动、卫生、排泄、睡眠、参与活动 | 区分看见、听说与未观察；保留数量/单位及来源 |
| 身体与心理观察 | 护士明确说出的观察、已测量数值、情绪/行为描述 | 不通过声音推测诊断、跌倒风险、认知水平或情绪结论 |
| 护理行为 | 明确完成的协助、测量、联系、升级处理及老人反应 | “准备做”不能写成“已完成”；识别拒绝/未完成 |
| 药物相关事实 | 护士明确记录的药物信息或已执行动作 | 保留剂量/单位/时间；不替代 eMAR/用药核对，不提供建议 |
| 沟通与跟进 | 联系对象、明确安排的下一步、交班信息 | 不编造已联系或已升级；未经执行的事项保持计划状态 |

历史时间线用于查阅已确认事实，不生成未经评估的趋势判断、临床预警或风险评分。“记录了老人情况”不应被对外表述成“自动临床监测”。

## 9. 数据结构与状态

### 核心对象

- **Resident：** tenant_id、resident_id、显示资料、授权访问范围；身份更改有历史。
- **ShiftSession：** nurse_id、机构/区域、起止时间、时区、设备、录音窗口、暂停原因、处理状态。
- **RecordingAuthority：** 适用人/场景、通知/同意或其他经确认依据、授权代表及权限范围、有效期、撤回记录；不把亲属关系当成自动授权。
- **AudioChunk：** 会话、序号、时间范围、文件校验、加密/上传/保留状态；不用于模型训练。
- **TranscriptSegment：** 时间范围、原文、说话人线索、听不清/重叠标记、来源指针、版本。
- **CareEvent：** 事件时间及精度、录制时间、记录对象、身份依据、事实类型、表达者/转述来源、计划/执行状态、原文证据范围、模型版本。
- **NoteDraft / SignedNote：** 老人、模板、引用事实、内容、人工修改、审核人、签署时间、版本与修订关系。
- **ExportJob / AuditEvent：** 提交目标、结果、幂等标识、操作者、对象、时间及变更原因。

tenant_id 必须贯穿对象、权限与任务处理。个人身份数据、可识别音频和健康内容不进入一般分析日志。

### 状态流转

处理：`采集中 → 上传中 → 转写中 → 归属待确认/已绑定 → 草稿 → 审核中 → 已签署 → 已导出/已提交`。

“处理失败”“录音缺口”“已排除”“未解决待交接”和“需修订”是独立可见状态。人工改变原始转写时保留原版本；正式签署后只新增有作者与理由的修订。前序事实/归属发生变化时，使相应未签署草稿失效并重新审核，避免提交旧内容。

来源回查受访问与保留政策约束：音频依法/按政策删除后，保留允许保留的转写证据、审核和版本信息；界面明确音频已不可回放，不能伪造完整音频追溯能力。

## 10. 主要页面

1. **班次首页：** 开始/暂停/结束、授权状态、设备/网络、已处理时长、录音缺口、待确认数量及记录完成进度。
2. **老人列表：** 机构授权名册、身份核对、当前 encounter、各老人本班次草稿数量；同名明显区分。
3. **老人情况页：** 已签署时间线、基本信息来源、单独展示的草稿和明确安排的跟进事项。
4. **待确认页面：** 原文/片段、归属线索及冲突原因、拆分/确认/排除/待交接操作。
5. **记录审核页：** 草稿与来源对照、事实与时间、人工编辑、关键字段检查、签署与导出结果。
6. **机构管理页：** 用户与权限、名册、模板、录音规则、授权状态、保留策略、供应商/集成配置及审计。

护理界面优先支持忙碌状态下的大按钮、可读文本、键盘/辅助技术及快速暂停。状态说明不用模型/管线等技术词汇代替护士需要知道的信息。

## 11. 非功能需求与建议目标

数值为首版候选目标，需原型测试、成本评估和试点临床负责人确认，不能作为已实现的营销承诺。

| 项目 | 候选目标 / 验证方法 |
|---|---|
| 单班容量 | 支持 480 分钟获授权音频、至少 20 位老人及对象频繁切换；名册和并发上限需客户确认 |
| 录音可靠性 | 选定设备完成 8 小时耐久测试，所有片段可核算；零静默丢失，任何缺口均告知用户 |
| 在线草稿时延 | 完整片段上传后，P95 在 5 分钟内出现转写/草稿或明确失败状态；模型/上传延迟分开测量 |
| 班后完成 | 网络稳定时，最后一段上传后 P95 15 分钟内完成处理；审核时间单独统计 |
| 断网恢复 | 在指定缓存容量内支持 30 分钟断网；录音权限有效时恢复上传，缓存满前告警并停止采集或提示切换手动方式 |
| 权限隔离 | 所有查询、生成任务、回放、导出及后台操作通过机构和角色隔离验证 |
| 音频安全 | 传输/存储/本地缓存加密；录音期间有清晰状态；后台/锁屏行为须在设备平台上验证 |
| 连续使用 | 评估电量、容量、麦克风、后台限制和携带方式；首版录音设备与终端尚未选定 |
| 可维护性 | 模型/提示词/模板版本可回查；更新有回归证据与回滚方案；供应商失败不自动切到未批准服务 |
| 使用成本 | 记录每护士班次音频分钟、转写/生成/存储成本和人工复核时间；预算上限待商业模型确认 |

不得简单假定“手机必然可连续后台录音 8 小时”。录音硬件、权限和设备策略是独立的可行性验证事项。

## 12. 澳洲隐私、录音与安全要求

长班次环境录音会涉及老人、同住者、员工、家属和访客，风险高于单次护士口述。产品设计必须把采集范围和暂停控制放在录音前，事后过滤不能补救不合法采集。

- **录音前：** 明确通知目的、AI处理、访问者、供应商/地点、保留和替代方式；记录合法依据及适用场景。机构批准和员工登录不能自动替代被录音者所需的告知/授权。
- **能力与代表：** 涉及认知障碍或代表同意时，确认适用法律、具体决定能力和代表授权；不默认家属就是合法代表。
- **场景控制：** 共享房间、公共区域、私人探访、休息区及其他人的对话必须有明确策略。无法落实采集边界时不启用该窗口；提供主动口述/手动记录。
- **撤回与意外采集：** 可立即暂停、撤回授权并走机构处理流程；意外收录标记、隔离并由隐私负责人评估删除/事件响应，不自动分发给老人档案。
- **用途限定：** 不将录音用于员工绩效监控、营销、声纹识别或共享模型训练；新用途需独立评估与相应授权。
- **数据流：** 按客户要求设计澳洲托管方案，核实模型、支持人员、日志、备份及所有分包商的实际处理地点；澳洲存储并不自动证明没有海外访问。
- **保留：** 音频、转写、草稿、已签署记录、审计和备份分别设定目的/期限/删除机制。原始音频默认尽量短期保留，具体天数待批准；不能把护理记录保留义务直接套用为整班次音频的保存期限。
- **发布：** 实施隐私影响评估、法律/录音规则评估、临床安全验证、供应商审查及公司现有 [试点准入清单](../Marketing%20%26%20Operations/Company%20OS/06_pilot_release_gate.md)。

## 13. 合成示例与错误处理

以下人物、身份和场景均为合成示例，不能当作实际用户反馈或实际护理记录。

**班次片段：** 护士在已确认 resident ID `DEMO-001` 的 encounter 中说：“林女士说左膝有点疼。刚才扶她坐到椅子上。午饭只吃了几口。我稍后联系 RN。”

**可生成的草稿事实：** 老人报告左膝疼痛；护士口述已协助坐下；午餐摄入量描述为“几口”；联系 RN 为计划事项，未确认已联系。事件时间如不明确，保留录制时间并标注具体发生时间未知。

**不能生成：** 疼痛 4/10、关节炎、跌倒高风险、已通知 RN、已给止痛药或午餐摄入 25%。它们均未由输入支持。

| 测试场景 | 期望行为 |
|---|---|
| 两位同名老人；护士仅说“Mary” | 不自动确认身份，进入待确认 |
| 对 A 说起 B 的情况 | 记录对象与说话人/当前对象分开，需足够依据 |
| “没有摔倒”被识别为“摔倒” | 否定表达可回查并修正；关键错误纳入发布验证 |
| “准备给药”或“她拒绝服药” | 不写成已给药；人工核对药物相关信息 |
| 录音持续但设备断网/重启 | 有缓存/恢复和明确缺口；不把无录音写成无事件 |
| 背景碰撞声或老人喊叫 | 不推断跌倒、原因或诊断；非清晰护理事实不生成结论 |
| 录音已暂停仍残留最后上传片段 | 按真实采集时间/授权边界处理；暂停后不继续采集，禁止用上传状态误报录音中 |
| 原始录音缺乏授权 | 导入/处理流程阻断并提示机构评估；不视为补勾选即可合法化 |
| 导出失败后重试 | 不重复生成正式记录；显示真实目标系统结果 |
| 身份已纠正但旧草稿仍在审核 | 旧草稿失效，重新核对后才能签署 |

## 14. 试点指标与发布条件

试点前用独立人工标注的模拟资料验证；建议包含至少 20 个完整班次、200 个 encounter，覆盖对象切换、同名、多说话人、背景噪音、断网和拒绝录音。最终样本量与真实试点范围由临床安全负责人确定；有限样本“零错误”不证明实际风险为零。

| 指标 | 计算方式 | 候选试点目标 |
|---|---|---|
| 老人错误归属 | 与人工基准不一致的绑定事实数 / 所有已绑定事实数；同时报告绝对数量 | 关键验证集中 0 个可直接进入签署的错误归属；发现即暂停并调查 |
| 自动归属覆盖率 | 无需人工重新归属的正确事实数 / 所有应记录事实数（含未归属） | 首版先建立基线；不能靠减少待确认项牺牲准确性 |
| 关键事实不支持/遗漏 | 错误或缺失的关键事实数 / 人工基准关键事实数 | 明确关键事实分类；危险错误是阻断项；阈值待临床签定 |
| 文书用时 | 每护士班次整理 + 复核 + 补录总分钟，配对比较原流程 | 候选中位数减少 30%；不能把审核时间排除 |
| 审核修正负担 | 每份草稿修改比例、时间及原因 | 建立基线并分析身份/事实/格式错误来源 |
| 音频完整性 | 预期已授权采集时长与可核算片段/已告知缺口的差异 | 0 个静默丢失；实际缺口单独报告 |
| 签署和提交正确性 | 授权人签署、正确对象、无重复记录的提交次数 / 总次数 | 准入验证全部通过 |
| 隐私与权限 | 意外采集、越权、跨机构泄露和拒绝后继续采集事件 | 0 个已知未处置重大事件；所有事件调查闭环 |
| 亚组表现 | 按口音、噪音、语言/沟通情况和设备分组 | 单独报告样本量与结果，不能用总体平均掩盖失败 |

在录音合法性未确认、住户授权流程不可落实、错误身份绑定、危险事实编造/遗漏、跨机构泄漏或录音暂停失效时停止相关试点。发布决定应包含实际证据、剩余风险、适用场景与签署负责人。

## 18. 市场分析、亮点与突破方向

### 18.1 调研支持的市场判断

以下基于公开产品资料与既有研究，并于 2026 年 10 月 4 日复查 MediQo、Acredia 与 AlayaCare 官方页面。供应商功能和收益声明未经过本团队现场或独立验证；页面未说明某项能力，也不能据此认定竞争者没有该能力。

| 竞品路线与例子 | 公开能力 | 对 careKind AI 的影响 |
|---|---|---|
| 护理现场语音文书：MediQo | 产品页描述护理互动生成记录、交班等文书，员工审核批准后进入记录流程。 | 单靠“听语音生成 note”不足以形成明显差异；必须验证多老人切换、归属与真实审核负担。 [官方页面](https://www.mediqo.health/solutions/aged-care-documentation) |
| 平台内摘要/来源追踪：Acredia Intelligence | 产品页展示 shift summaries、resident history、来源和人工审阅。 | 来源追踪也是已有竞争方向，需要将它贯穿录音、事实、草稿、签署与修订，而不仅展示摘要来源。 [官方页面](https://acredia.au/intelligence/) |
| 综合平台 AI：AlayaCare | 澳洲产品页列出语音表单辅助、问答/摘要和工作流功能。 | 大平台有渠道和既有流程优势；careKind 初期适合选择一个机构、一类高频工作流和一个明确集成目标。 [官方页面](https://alayacare.com/en-au/) |
| 通用 scribe 与早期工具：Heidi、Notive 等 | 已有研究列出可编辑记录、模板/口述等公开能力，详见竞品报告。 | 护士可能已有替代工具；访谈应比较实际操作步骤、费用、准确性与机构接入，不能只比较生成文本。 |

**建议定位：** 澳洲养老机构内的护士班次文书助手。它在一个班次里管理多位老人的信息归属、事实来源、审核状态和交班输出。客户购买的价值是少整理、少重复输入、记录可查证和工作流可落地。

### 18.2 五个值得验证的亮点

| 亮点 / 突破假设 | 产品怎么体现 | 如何证明 |
|---|---|---|
| 多老人班次归属 | 班次名册、短 encounter 身份标记、主题切换、未知/冲突队列 | 独立标注的整班次测试；同时测错误归属和覆盖率，不只测转写准确率 |
| 一次护理事实，多份适用文书 | 先形成可溯源事件，再生成老人 progress note 和班次交班摘要；之后映射机构表单 | 比较总录入/审核时间与字段一致性，检查同一事实是否在不同文书中被改写失真 |
| 快速但有依据的审核 | 字段点击可回查片段/转写；身份、数值、否定、计划/执行冲突突出显示 | 与整篇人工重读对比审核时间、错误发现率和漏检率；减少时间不能以跳过审核为代价 |
| 老人事实时间线 | 按实际事件时间呈现已签署情况；来源与作者明确，草稿独立可见 | 交班时能否正确找到变化、护理动作和未完成的明确安排；不宣称临床预警能力 |
| 机构可部署的采集与回写 | 授权窗口、快捷暂停、拒绝替代流程、权限隔离、导出/指定系统回写 | 客户现场演示、授权流程演练、设备耐久/断网测试、正确档案回写验证 |

这些是产品可验证的差异化方向，不是行业首创、专利或已建立壁垒的结论。长期积累来自经授权的机构模板映射、实际集成、可复现评估集、护士使用证据和纠错机制；不能把收集大量住户录音作为默认增长策略。

### 18.3 发展路径与商业验证

- **起点：** 选择愿意合作的一家 residential aged-care 机构，先做一个区域、少量护士的 progress notes 与交班流程。确认购买者、临床审批者、IT/隐私审批者和实际使用者，记录现有系统与文书用时。
- **首个价值闭环：** 明确老人身份 → 收集授权输入 → 自动整理草稿 → 护士审核 → 导出/回写指定老人档案。只有停在生成页面而还需大量复制粘贴，价值尚未验证。
- **扩张条件：** 归属、关键事实、录音合法性、审核负担和经济性达标后，再增加区域、护士、表单和机构。每种新照护环境重新验证，不能把一个机构的结果泛化为全澳洲有效。
- **集成策略：** 初期保持现有 CMS 为正式记录系统；选择客户已有的一套系统评估合作/接口。未接入时提供明确的受控导出流程，不宣传不存在的集成。
- **商业模式假设：** 机构订阅，加明确的活跃用户/音频处理额度；合同清楚说明额度、支持和超量成本。定价与每班次预算待访谈与成本测算，不复制竞争者未经核验的报价。
- **成本验证：** 每机构毛贡献 = 实收收入 − 转写/模型调用 − 存储/网络 − 支持/审核相关服务成本；同时计算客户的净时间收益。将 480 分钟全量处理与选择性采集进行对比，不能只计算摘要生成费用。
- **推广口径：** 试点前可展示合成演示；试点后仅宣传有方法、样本、适用范围和客户授权支持的结果。不给 funding 增长、自动合规或护理效果作未经证明的保证。

## 19. 产品实现逻辑

实现建议是分层处理，避免让模型直接阅读整班次录音后输出无法核查的“老人最终档案”。具体技术栈留待开发团队评估。

### 19.1 六层逻辑

| 层 | 输入 → 输出 | AI 与确定性规则的责任 |
|---|---|---|
| 采集层 | 授权状态、会话、设备输入 → 加密音频块及缺口记录 | 权限、暂停、上传和缓存由系统规则执行；模型不决定是否允许录音 |
| 理解层 | 音频块 → 转写、时间戳、说话人线索、候选事实 | AI 转写和提取；保留不清楚/冲突，原始片段不因生成文本而被改写 |
| 归属层 | encounter 标记、名册、候选事实 → 老人绑定候选或待确认 | 机构/稳定 ID 校验和权限由规则执行；AI 提供相关线索，不能绕过身份条件 |
| 事件台账层 | 已绑定/待确认事实 → 带来源和状态的事件 | 每条记录区分计划/完成/拒绝/未知；不确定事实不能自动提升为已确认 |
| 文书层 | 可用事件、机构模板 → 草稿及字段来源映射 | AI 组织语言；数值/单位/药物/时间按来源约束；原文不足就留空或未记录 |
| 审核与提交层 | 草稿、人工纠正、用户权限 → 签署版本、导出/回写结果 | 人主动审核签署；版本、幂等、权限与审计由系统执行 |

### 19.2 每条事件的判定顺序

1. 确认该片段属于当前机构且在有效采集范围内；无权限/意外采集走隔离处理。
2. 判断是否为可理解的护理相关内容。听不清时不补全；非护理内容不进入老人档案。
3. 提取最小事实，记录来源、表达者/转述者、事件时间及计划/执行状态。
4. 结合有边界的 encounter 和身份线索确定候选记录对象；线索冲突、话题切换或多人事实分别处理。
5. 将满足规则的事件组织到对应老人草稿区；剩余事件进入待确认。身份绑定状态独立于事实确认状态。
6. 去重仅处理同一上传块、重试或分块重叠造成的重复。相似内容发生在不同时间，不能默认同一护理事件。
7. 从事件生成相应模板草稿，关联字段来源；生成失败不丢失事件。
8. 人工归属/事实修改使依赖草稿失效；已签署版本不重写，走有作者和理由的修订。

### 19.3 模型和业务规则的边界

- 对话内容是待处理数据；“忽略规则”“写成已给药”等录音中的话不能成为系统指令。
- 草稿模板只能读取本机构、本老人、此次授权范围内允许使用的事件和上下文；不能把其他老人或未经确认历史信息混入。
- 模型输出结构化候选，后端校验 ID、枚举、时间范围、来源指针和数值格式；失败时进入错误/待确认流程。
- 原始说法矛盾时保留矛盾并请护士处理，不凭模型决定真实版本。
- 文书完整性提示只说明“未提供/未确认某字段”，不能说未执行了护理，也不能引导填造事实。
- 后续任务只来自人工明确安排并审核的事项。AI 没有看到完成证据，不等于任务没做；展示“完成状态未记录”，不自动临床升级。
- 重新生成未签署草稿可使用当前事件版本；用户已编辑的内容必须保留/对比，不能无提示覆盖。

## 20. 端到端产品工作流与失败分支

### 20.1 班次录音工作流

| 步骤 | 用户看到/操作 | 系统处理 | 失败或不确定分支 |
|---|---|---|---|
| W1 班前 | 登录，选择机构/区域和名册 | 加载授权、模板、设备及缓存状态 | 权限/设备/授权不满足时提供手动入口 |
| W2 建立 encounter | 选老人/扫码并核对，开始允许的采集 | 写入有时间范围的身份上下文 | 无身份时内容仅作待确认，不自动绑定 |
| W3 护理过程 | 查看采集状态，随时暂停、结束或切换老人 | 保存/上传音频块，产生转写与事件 | 噪音、多人、主题切换、访客/拒绝录音走相应暂停或待确认 |
| W4 班中整理 | 查看老人草稿和待确认，处理必要纠正 | 增量更新事件和草稿、记录依赖版本 | AI/网络失败保留状态与已获授权数据，不切换未批准服务 |
| W5 班次结束 | 停止录音，核对缺口和未解决事项 | 完成尾段处理、显示各老人准备状态 | 仍处理中不显示已完成；未解决事项可明确交接 |
| W6 老人审核 | 逐老人核对身份与事实，点击回查来源，编辑 | 记录修改人与原因，重算受影响草稿 | 缺来源、冲突或身份未确认阻止相关记录签署 |
| W7 签署提交 | 主动签署选定记录，查看导出/提交结果 | 创建不可静默改写的签署版本；正确 ID 回写 | 目标未知或超时标记状态未知并核查，不盲目重复提交 |
| W8 班后与保留 | 交班、查看已签署时间线、处理修订 | 同步可见性、权限、保留/删除和审计 | 修订走正式版本；保留阻断/删除失败升级运营处理 |

### 20.2 已有 8 小时录音工作流

登记来源/录制时间/授权 → 确认可以处理的范围 → 上传校验与分块 → 关联当时机构名册和身份标记（如有） → 转写/事实提取 → 提交归属候选和待确认队列 → 护士审核 → 签署/导出。

导入缺少现场 encounter 标记时，人工归属成本可能更高；产品必须显示该限制。录音文件本身不能保证里面的所有事实有身份依据、完整覆盖当班护理或可合法处理。

### 20.3 同一事实对应文书的工作流

先有一个带版本和来源的护理事件，progress note 与交班摘要分别引用该事件。护士修改事实时，未签署的相关文书都提示需更新；已签署文书保持原版本并按机构修订流程处理。首版允许分别审核，禁止“一键全部签署”掩盖未解决身份或关键事实。汇总摘要不改变事实的原始状态和作者。
